### 1. Фоновое изображение рабочего стола по IP и локации (с фоллбэком)
**Статус:** ✅ Выполнено  
**Приоритет:** Высокий  
**Компоненты:** `src/components/xp/desktop.tsx`, `src/components/xp/window-manager-context.tsx`, Next.js Middleware / Route Handlers, `src/components/xp/apps/display-properties-dialog.tsx`

#### Описание задачи:
Динамически определять локацию посетителя по IP-адресу при первом заходе и устанавливать соответствующее тематическое фоновое изображение рабочего стола (например, обои под конкретные регионы/города/страны или время суток).

#### Требования и детали реализации:
- **Определение локации:**
  - Использовать заголовки провайдера хостинга (`x-vercel-ip-country`, `cf-ipcountry` и т.д.) или легковесный серверный endpoint / middleware с fallback на бесплатный сервис геолокации по IP (например, ipapi / geoip).
  - Запрос должен выполняться асинхронно с таймаутом, чтобы задержка сети не блокировала отображение интерфейса.
- **Фоллбэк:**
  - Если локация не определена, сервис недоступен, запрос завершился по таймауту или для данной локации нет отдельного фона — по умолчанию устанавливается классический Bliss (`/images/bliss.jpg`).
- **Приоритет пользовательского выбора:**
  - Если пользователь уже вручную выбрал обои через диалог «Свойства экрана» (`display-properties-dialog.tsx`) или сохранил рисунок из Paint (`amazi-xp-wallpaper` в `localStorage`), автоматическая смена по IP не должна перетирать явный выбор пользователя.
- **UX / Плавность:**
  - Плавное появление (fade / crossfade) фонового изображения без мерцания белым фоном при подгрузке.

### 2. Лидерборды в играх (с рандомными значениями для наполнения)
**Статус:** ✅ Выполнено  
**Приоритет:** Средний  
**Компоненты:** `src/components/xp/apps/minesweeper-window.tsx`, `src/components/xp/apps/solitaire-window.tsx`, `src/lib/xp/games/`

#### Описание задачи:
Добавить в игры («Сапёр» и «Косынка / Солитер») таблицы рекордов (Leaderboards / High Scores). Для полноты и реалистичности списка на текущем этапе наполнить таблицу сгенерированными правдоподобными значениями.

#### Требования и детали реализации:
- **Сапёр (Minesweeper Pulse):**
  - Таблица рекордов для каждого уровня сложности: Sprint, Новичок (Beginner), Любитель (Intermediate), Эксперт (Expert).
  - Параметры рекорда: место, имя/ник игрока, затраченное время (секунды), дата рекорда.
  - Генерация моковых соперников: 5–10 записей на каждый уровень с реалистичным временем и ностальгическими никами (в духе XP-эпохи).
  - Поддержка записи собственного рекорда пользователя: при победе, если результат входит в топ, запрашивать ник и сохранять в `localStorage`.
- **Косынка (Solitaire Atelier):**
  - Таблица лучших результатов: время партии, количество ходов, набранные очки.
  - Моковый топ игроков с реалистичными результатами.
  - Сохранение личных лучших партий пользователя в `localStorage`.
- **UI / UX:**
  - Кнопка вызова таблицы рекордов (в меню игры или верхней панели).
  - Окно / модалка рекордов в аутентичном XP-стиле (с рамкой и кнопкой «Сбросить» / «Закрыть») либо в стилистике премиум-дизайна самой игры.
  - Выделение результата текущего игрока в списке.

### 3. Сквозная Яндекс.Метрика на каждый элемент страницы
**Статус:** ✅ Выполнено  
**Приоритет:** Средний / Высокий  
**Компоненты:** `src/app/layout.tsx`, `src/lib/analytics.ts`, `src/components/analytics/yandex-metrika.tsx`, `src/components/xp/`, `src/components/portfolio/`

#### Описание задачи:
Интегрировать счетчик Яндекс.Метрики и настроить детальную сквозную аналитику взаимодействий пользователя со всеми интерактивными элементами операционной системы и приложений.

#### Требования и детали реализации:
- **Базовая интеграция:**
  - Инициализация скрипта Яндекс.Метрики через компонент в Next.js `layout.tsx`.
  - ID счётчика через переменную окружения `NEXT_PUBLIC_YM_ID` (с безопасной заглушкой в development-режиме, чтобы не слать тестовый трафик).
  - Включение Webvisor (вебвизор), карты кликов и карты скролла.
- **Декларативный трекинг кликов и событий:**
  - Создать легкую утилиту / хук `reachGoal(goalName, params)` и механизм глобального делегирования кликов по `data-ym-goal="<цель>"` или `data-analytics="..."`.
  - Автоматический или декларативный сбор событий при кликах, исключающий необходимость вручную спамить `onClick` во всех компонентах.
- **Объекты разметки:**
  - **Рабочий стол:** клики по иконкам (`Мой компьютер`, `Корзина`, `Портфолио`, `Paint`, `Косынка`, `Сапёр`, `Справка`), контекстное меню.
  - **Панель задач и меню «Пуск»:** кнопка «Пуск», пункты меню, трей (часы, громкость, обои).
  - **Окна:** кнопки «Свернуть», «Развернуть», «Закрыть», перемещение и изменение размера.
  - **Портфолио / Кейсы:** переходы по ссылкам проектов, просмотр демонстраций, скачивание файлов/резюме.
  - **Игры:** старт новой игры, выбор сложности, подсказка (hint), ход/отмена (undo), победа/поражение.
  - **Внешние ссылки:** клики по контактам (Telegram, GitHub, email и др.).
