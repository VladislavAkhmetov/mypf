## Зафиксированная концепция

- При обычном входе открыт крупный короткий документ «Обо мне» в Word без боковой панели.
- На рабочем столе нет большого слогана. Основные профессиональные входы: «Обо мне», «Портфолио», «Резюме.pdf».
- «Портфолио» использует существующую иконку Internet Explorer и открывает одно большое браузерное окно.
- Внутри браузера позднее появится современный авторский лендинг: крупная типографика, визуальные кейсы, работающие прототипы, анимации прокрутки и локальные экранные эффекты. Референс направления: https://pxpush.com/. Не копировать его контент и графические материалы.
- Обычная ссылка открывает Word; специальные ссылки сразу открывают портфолио, подборку или проект.
- Позиционирование: коммуникационный дизайн и создание работающих интерактивных прототипов с помощью AI. Не приписывать автору подтверждённую квалификацию production-разработчика.
- Общий будущий масштаб оболочки должен давать ощущение меньшего разрешения монитора: крупнее иконки, подписи, панели и управление. На этом этапе только составить карту зависимостей размеров; глобальный масштаб не менять.

Последняя концепция заменяет конфликтующие предложения старых дизайн-документов о тексте на рабочем столе, стартовом каталоге и боковой панели Word. Игровое ТЗ остаётся отдельной областью.

## 1. Короткий Word и вход

Добавь отдельный краткий профиль в существующую структуру документов. Старые эссе не переписывай и не удаляй. Для краткого профиля используй slug `profile`, заголовок «Влад Ахметов» и следующий текст без расширения биографии:

**Подзаголовок:** «Коммуникационный дизайн и интерактивные прототипы».

**Текст:** «Я занимаюсь коммуникационным дизайном и создаю работающие интерактивные прототипы с помощью AI-инструментов. Мне интересны задачи на стыке визуальной коммуникации, интерфейсов и их поведения».

**Действия:** «Посмотреть проекты» открывает портфолио; «Резюме» открывает существующее окно резюме. Контакты переиспользуй из `site.ts`, не создавай новые адреса. В отчёте отметь, что контакты и резюме требуют подтверждения владельцем; не добавляй такое служебное сообщение на страницу.

Не заполняй отсутствующий опыт выдуманными компаниями, годами, клиентами, цифрами, наградами или навыками. Не выводи пустые разделы и заглушки. Профиль можно позднее дополнить подтверждёнными фактами.

Макет задан: одна белая текстовая колонка до 820 CSS px, поля 48 px на десктопе и 20 px на телефоне; основной текст 20 px / 1.55, заголовок 40 px на десктопе и 30 px на телефоне. Выравнивание слева, без выравнивания по ширине. Бумага не обязана имитировать фиксированный A4. Нет оглавления, левой панели, даты публикации, подписи автора под его же именем и счётчика слов у краткого профиля. На панели краткого профиля достаточно названия документа и доступа к прежним документам через один компактный селектор. Не оставляй нефункциональные кнопки. Прежние документы должны открываться без потери содержимого.

Создай единый запуск профиля, используемый при входе, с рабочего стола и из меню. Повторный запуск фокусирует существующее окно и действительно переключает его на `profile`, даже если до этого читали другое эссе. Учти, что сейчас initialDocSlug используется для начального локального state.

Начальные размеры обоих основных окон: на ширине от 1024 px — 90% ширины и 92% доступной высоты, по центру рабочей области. Доступная высота исключает фактическую панель задач; не добавляй новый литерал `46` в расчёты. Ниже 1024 px — вся доступная рабочая область. После уменьшения viewport управление окном остаётся доступным. Геометрию вынеси в маленькую общую функцию, не переписывай весь менеджер окон.

Чистый вход без специальных параметров открывает только Word с профилем, без пустого рабочего стола или старого эссе перед ним. Инициализация идемпотентна, без таймера для маскировки гонки и без ошибок hydration.

Это рабочая интеграционная версия на существующих данных, а не новый демонстрационный дизайн. Не добавляй mock-проекты, Lorem ipsum и декоративные заглушки.

## 3. Ссылки и навигация

Сохрани совместимость `?project=slug`; существующие ссылки должны открывать соответствующий кейс внутри нового браузера. Для ручной проверки используй существующий `?project=kora`.

Поддержи точный контракт:

| URL-параметры | Стартовое содержимое |
| --- | --- |
| Без параметров | Word, краткий профиль |
| `?view=profile` | Word, краткий профиль |
| `?view=portfolio` | Браузер, общий каталог |
| `?view=portfolio&focus=communication` | Браузер, коммуникационное направление |
| `?view=portfolio&focus=engineering` | Браузер, интерфейсы и прототипы |
| `?project=kora` | Браузер, кейс Kora |

Известный `project` имеет приоритет над `view`; `focus` сохраняется для возвращения к подборке. Неизвестный project ведёт в каталог с коротким сообщением «Проект не найден». Неизвестный focus означает общий каталог; неизвестный view без project означает профиль. Посторонние query-параметры сохраняй.

Вынеси разбор адреса в чистую небольшую функцию. Для двух направлений сделай явные списки существующих slug в одном конфиге, исходя из текущих описаний; отметь в отчёте, что это предварительная классификация. Не переписывай опыт или описания под вакансию и не считай этот конфиг подтверждением достоверности проектов.

Раздели открытие представления и запись в history: загрузка и popstate не должны создавать новые записи. Пользовательские переходы должны поддерживать Back/Forward реального браузера без дублей окон и циклов. Прямые ссылки сразу открывают целевое окно без промежуточного Word. Закрытие браузерного окна убирает его параметры через replace, не открывает Word немедленно; следующий reload обычного URL открывает профиль. Минимизация URL не меняет. Используй единую логику запуска для desktop, Start и существующих ссылок на проекты.

## 5. Самопроверка и сдача

Исполнитель сам запускает приложение и проверки, просматривает скриншоты и исправляет найденные дефекты. Не передавай лиду задачу «проверь, работает ли».

Добавь целевые тесты чистого разбора URL и приоритета параметров, а также небольшой Playwright-набор `e2e/portfolio`. Расширь testDir конфигурации так, чтобы запуск новых тестов работал и существующий `npm run test:e2e:games` продолжал выбирать игры. Не изменяй смысл старых проверок ради зелёного результата. Отдельные snapshot-тесты текста и проверка существования каждого CSS-класса не нужны.

Обязательные сценарии:

1. Чистый вход → ровно один профиль; крупный текст, нет боковой панели и DesktopHero.
2. Переход из Word, ярлыка и меню → один браузер; повторное открытие не дублирует окно.
3. Все варианты URL из таблицы, неизвестные значения и сочетание project/focus/view.
4. Каталог → кейс → назад; настоящий browser Back/Forward; reload прямой ссылки. Проверяй и URL, и видимое содержимое.
5. Минимизация/восстановление сохраняют кейс и прокрутку; закрытие и повторное открытие работают.
6. На 1920×1080, 1366×768 и 390×844 нет горизонтального overflow документа и недоступных кнопок окна; основной контент нормально прокручивается. Проверить реальное уменьшение viewport при уже открытом окне.
7. Клавиатура: Tab, видимый фокус, Enter/Space на действиях, доступные названия управления. Телефон не требует двойного клика или перетаскивания для перехода к проектам.
8. Нет новых pageerror, hydration errors и сломанных запросов локальных ассетов.

Финальные команды, по одной после последних исправлений: `npm run lint`, `npx tsc --noEmit`, `npm run build`, `npx vitest run`, `npx playwright test e2e/portfolio`, `npm run test:e2e:games`. Playwright использует production-сервер на 3100 и требует build. Не завершай чужие процессы, чтобы освободить порт. Если порт занят, используй отдельный согласованный через конфиг тестовый порт без изменения пользовательского dev-сервера.

После локального исправления сначала повтори упавший целевой тест; полную проверку повторяй только когда изменения затрагивают общую основу. Внешний сбой скачивания, отсутствующий браузер или старый lint failure отражай как реальный блокер, а не PASS. Исправляй собственные регрессии; старые несвязанные проблемы перечисли отдельно с исходным результатом.

Сохрани шесть реальных скриншотов: Word и браузер на трёх указанных размерах, в `docs/design/qa/portfolio-foundation/`. Для браузера на 1920 покажи каталог, на 1366 — кейс, на телефоне — каталог. Просмотри каждый, исправь обрезания, наложения и лишний скролл. Скриншоты не доказывают финальное визуальное качество лендинга: оно вне этапа.

Оставь `docs/design/portfolio-foundation-report.md` объёмом до 35 строк: READY или BLOCKED именно для подготовки, изменённые области, фактические PASS/FAIL/NOT RUN по командам, ссылки на шесть скриншотов и опись, оставшиеся ограничения. Результат этапа — работающие Word, оболочка, переходы и ссылки, сохранённая совместимость, проверенные материалы и короткая техническая сдача. Лид получает основу для визуальной работы без повторного исследования проекта.
