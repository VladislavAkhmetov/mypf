Это план будущей реализации, основанный на чтении текущего кода и официальной документации библиотек. ## 1. Задание исполнителю

Реализуй полный редизайн существующих игр «Косынка» и «Сапёр» по этому документу. Работай в текущем Next.js-проекте. Доведи обе игры до полноценной партии: правила, графика, управление мышью/touch/клавиатурой, эффекты, сохранение, завершение и проверка. Последовательно выполняй этапы из раздела 9; после каждого проверяй результат и продолжай. В финале предоставь реальные скриншоты, описание изменений, результаты проверок и оставшиеся ограничения.

Главный приоритет — визуальное качество и удовольствие от взаимодействия. Солитер должен ощущаться как дорогая коллекционная колода на столе частного карточного салона. Сапёр — как сочная, быстрая аркада с физически убедительными кнопками и выразительной реакцией на каждый ход.

Внешняя оболочка окон XP связывает игры с портфолио. Внутри окна каждая игра получает самостоятельную современную арт-дирекцию. Пользовательские надписи — на русском. Atelier и Pulse — названия визуальных направлений; названия приложений остаются понятными: «Косынка» и «Сапёр».

Актуальный запрос на люксовый солитер и яркий динамичный сапёр уточняет прежние визуальные предложения в `docs/design/personal-desktop-design-v2.md`, раздел 11. Базовые правила из `docs/design/xp-portfolio-design-doc.md`, раздел 15, сохраняются с явно описанными ниже дополнениями. Не распространяй редизайн на остальные приложения.

Наблюдения по коду, которые нужно закрыть при реализации:

1. В солитере ручной переворот закрытой карты мутирует объект через `card.isFaceUp = true` после поверхностного копирования состояния. Это может повредить предыдущий снимок Undo. Все изменения перенести в чистый движок.
2. `drawCard` увеличивает число ходов, даже когда запас и сброс пусты. Нулевое действие не должно менять состояние, счётчик и историю.
3. `HintMove` не содержит индекс карты внутри колонки, хотя поиск находит последовательности с разных позиций. Добавить точный источник — `cardId` и индекс.
4. Возврата из основания в колонку в движке пока нет. Добавить легальный обратный перенос верхней карты, чтобы игрок мог исправлять стратегию.
5. Солитер считает время сразу после запуска. Начинать с первого изменения партии, исключая просмотр правил и выбор карты.
6. Состояние и история солитера локальны компоненту; состояние сапёра тоже. При размонтировании возможна потеря партии. Нужен устойчивый session store и локальное сохранение.
7. В UI сапёра быстрый выбор включает sprint/beginner/intermediate, хотя engine содержит expert. Сделать доступными все четыре уровня и проверить адаптивность.
8. Старое окно сапёра с рабочего стола имеет размер 340×450. Такой размер тесен для нового интерфейса: пересмотреть его вместе с другими точками запуска.

Перед написанием Next.js-кода прочитай локальные руководства установленного пакета: `node_modules/next/dist/docs/01-app/02-guides/lazy-loading.md` и `node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md`. Учитывай `AGENTS.md` проекта.

Рекомендация: React DOM + SVG для игрового поля, Motion для движения, dnd-kit для переноса карт, Canvas 2D для коротких частиц. Существующие чистые TypeScript-движки остаются источником правил. Для двух небольших полей это позволит вложить работу в авторскую графику и точное взаимодействие.

Перед установкой проверь peerDependencies и engines выбранных стабильных версий относительно React 19, TypeScript и локального Node. Зафиксируй разрешённые версии в npm lockfile. Не обновляй Next.js/React ради этого редизайна. Базовый набор установки после этой проверки:

Рассмотренные альтернативы:

- [fSolitaire](https://github.com/fuzzley/fSolitaire) — готовая реализация с несколькими пасьянсами; README описывает Angular/Phaser. Для текущего React DOM-проекта интеграция потребует другой архитектуры. Здесь использовать собственный имеющийся движок.
- [JSMinesweeper](https://github.com/DavidNHill/JSMinesweeper) — готовые player, solver и analyser. Полезный кандидат для будущего режима логического анализа; для обычного сапёра текущий движок уже покрывает основу. В этот выпуск solver не включать.
- [PixiJS ParticleContainer](https://pixijs.com/8.x/examples/basic/particle-container/) — возможное развитие эффектов, если измерения покажут необходимость большого числа спрайтов. Для заданного лимита частиц начать с Canvas 2D.
- [Howler](https://howlerjs.com/) имеет смысл при большой библиотеке аудио; сейчас расширение существующего аудиосервиса проще второго параллельного слоя.

Сторонние примеры — ориентиры по возможностям; готовый интегрированный пакет игр не найден и не проверен. При заимствовании реального кода или ассетов проверить их лицензию и сохранить обязательную атрибуцию.

## 4. Солитер Atelier: коллекционный предмет

### Впечатление и композиция

Тихая роскошь: плотное изумрудное сукно, тёплая бумага, винная краска, почти чёрные пики и трефы, гравированная графика, тонкое матовое золото. Свет идёт сверху слева и одинаков для стола, карт и элементов интерфейса. Ощущение премиальности строится на качестве рисунка, полях, глубине стопки и движении.

Фон стола — глубокий зелёный с мягким световым пятном над центром расклада и лёгкой виньеткой по краям. Мелкая статичная фактура сукна видна при внимательном рассмотрении. Рамка игрового стола — узкий тёмный кант; крупные позолоченные панели и постоянные сияния перегрузят композицию.

Верхняя внутренняя панель: «Косынка», небольшой знак масти, справа время и число ходов. Под ней поле: запас и сброс слева, четыре основания справа, семь колонок ниже. Оси верхнего ряда и колонок согласованы. Внизу компактные действия «Новая», «Отменить», «Подсказка», «Колода», «Настройки». На узком окне второстепенные действия уходят в доступное меню.

В исходном размере окна ориентироваться на 960×720 CSS px, ограничивая его доступной рабочей областью. При меньшей высоте поле прокручивается внутри; панель управления остаётся доступной. Максимизированное окно даёт картам больше воздуха, но не растягивает их до размера плакатов.

### Авторская колода

Карта имеет пропорцию примерно 5:7. Ширина на просторном поле 88–104 px. Внешний радиус около 7% ширины. Бумага слегка тёплая, край тонкий, тени многослойные и мягкие. У стопки заметна толщина через 2–3 смещённых торца, количество декоративных слоёв ограничено.

Угловые индексы располагаются действительно в верхнем левом и нижнем правом углах; нижний повёрнут на 180°. Верхний индекс читается в перекрытой колонке. Величину вертикального перекрытия выбирать из размеров индекса и масти.

Карты 2–10 получают корректное число знаков масти в продуманной симметричной сетке. Одна крупная масть вместо всех числовых композиций не отвечает задаче коллекционной колоды. Тузы — крупный гравированный символ с тонким орнаментом. Валет, дама, король — настоящие авторские векторные фигуры с двусторонней композицией, собственным силуэтом и атрибутами. Типографическая буква K/Q/J сама по себе недостаточна.

Сделать три базовые композиции фигур и четыре варианта каждой: уникальные атрибуты, узор ткани, символ масти. Все 12 фигур должны выглядеть одной серией. Достаточна выразительная ограниченная графика: тонкая гравюрная линия, большие пятна, 3–4 краски. Мельчайшая детализация не должна исчезать в игровом масштабе.

Рубашка: центральный медальон VA, симметричная геометрическая гильошировка, двойная рамка, изумрудный фон и матовое золото. SVG повторяющиеся узоры определить один раз; не дублировать тысячи одинаковых path на каждой карте. Общие SVG id не конфликтуют между экземплярами.

Обязательный экран «Колода»: сетка всех 52 карт и увеличенный просмотр выбранной карты, переключение лицевая/рубашка, возврат в партию. Одна законченная колода обязательна; дополнительные темы отложены.

Сначала создать визуальный эталон из рубашки, A♠, 7♥, Q♦ и K♣, затем на его языке собрать остальную колоду. Итоговые ранги и масти должны быть векторными и точными; изображение целого игрового поля не является рабочим интерфейсом.

### Движение и ощущения

| Действие | Реакция | Начальный ориентир |
| --- | --- | --- |
| Раздача | Карты летят из запаса и укладываются последовательно | Интервал 22–30 мс, вся сцена до 1,2 с |
| Наведение | Лёгкий подъём, мягкая тень | 2–3 px, 100–140 мс |
| Захват | Вся переносимая последовательность приподнимается | Scale до 1,035, наклон до 2° |
| Перемещение | Карты следуют указателю без задержки; допустимая цель получает тонкий контур | Никакой интерполяционной задержки самого drag |
| Успешный перенос | Короткая посадка и исчезновение подсветки цели | 180–240 мс |
| Недопустимый перенос | Спокойный возврат к исходной стопке | 180–220 мс |
| Переворот | Вращение по Y с корректными двумя сторонами | 200–260 мс |
| Подсказка | Контур источника и цели плюс точный текст хода | Два мягких импульса, затем покой |
| Победа | Финальные карты занимают основания, золотой свет проходит по четырём стопкам | 1,5–2,5 с, можно пропустить |

Перелёт одной карты в основание может получить едва заметный блик. При обычных ходах не распылять конфетти. Звуки при включённом аудио: короткий бумажный шелест, приглушённая посадка, мягкий аккорд победы. Частые звуки имеют небольшие вариации и ограничение полифонии.

### Правила и управление

Обязательный режим — Klondike/Косынка: 52 карты, семь колонок 1–7, верхние открыты, добор по одной, неограниченный повторный проход запаса. Основания строятся A→K по масти; колонки — по убыванию с чередованием цвета; пустое место принимает короля или корректную последовательность с королём. Открывать освободившуюся закрытую карту автоматически в той же транзакции.

Перенос: drag всей корректной последовательности или «выбрать источник → выбрать цель». Double click/double tap на доступной верхней карте отправляет её в основание, если ход допустим. Обработчики click/double click и drag должны исключать двойное применение хода. Верхнюю карту основания можно вернуть в колонку по обычным правилам.

Клавиатура: Tab проходит между управлением и полем, стрелки перемещают фокус, Enter/Space выбирает карту или подтверждает цель, Escape отменяет выбор, Ctrl/Cmd+Z отменяет ход. Все команды работают только в активной игре и не перехватывают ввод в полях/других окнах. Если на кнопке указана F2, клавиша действительно запускает действие.

Undo не ограничен в пределах сохранённой сессии: восстанавливает все стопки, открытость карт и счётчик ходов. Время остаётся фактически сыгранным и назад не откатывается. Счёт очков убрать из основного UI; время и ходы достаточны и понятны. Логический ход — успешный добор, повторный проход или перенос, включая автоматический переворот; выбор, отмена выбора и неверный drop не считаются.

Подсказка показывает легальный ход без доступа к скрытым картам и без обещания победы. Отсутствие найденной подсказки не означает доказанную нерешаемость.

«Завершить автоматически» доступно только при пустых запасе и сбросе, всех открытых картах и успешном предварительном проигрывании легальных переносов до победы на копии состояния. Если симуляция зашла в тупик — кнопку не предлагать. Выполнение допускает остановку; Undo возвращает состояние до автозавершения одним действием.

На телефоне шириной 390 px ориентир для карты около 44–46 px с сокращёнными промежутками; ранги и доступная верхняя часть должны оставаться читаемыми. При ширине менее 360 px использовать поле с минимальной шириной и явной горизонтальной прокруткой. Для плотной длинной колонки предусмотреть увеличенный выбор карт после нажатия на колонку; содержимое закрытых карт не раскрывать. Управление «выбрать → поставить» обязательно, перетаскивание — дополнительный способ на touch.

## 5. Сапёр Pulse: цвет, рельеф, энергия

### Впечатление и композиция

Небольшая настольная аркадная машина: тёмный чернильный корпус, закрытые клетки из синего глянцевого материала, яркие коралловые флаги, лаймовые акценты, светлая читаемая цифра. Напряжение и радость создаются быстрым нажатием, волной раскрытия и короткими всплесками энергии.

Верхняя панель: оставшиеся по счётчику мины, центральная кнопка перезапуска с авторским SVG-персонажем, время. Персонаж реагирует на нажатие, победу и поражение; системные emoji заменить единым рисунком. Под панелью переключатель сложности, ниже крупное поле. В нижней панели — «Открывать / Флаг», прогресс безопасных клеток и настройки.

Вместо стены одинаково светящихся элементов выбирать один главный акцент текущего действия. Фон в покое статичен, поле неподвижно. Цифры видны сразу после открытия, декоративный эффект не задерживает чтение следующего хода.

Закрытая клетка имеет заметную верхнюю плоскость и нижний торец 3–4 px. Нажатие опускает плоскость к торцу. Открытая клетка лежит ниже закрытых. Флаг — чёткий объёмный значок со стойкой и читаемым полотном. Мина — узнаваемая авторская пиктограмма с ядром и шипами. Поражение различает взорванную мину, другие мины, верные и ошибочные флаги.

Для 16×16 и 16×30 использовать прокрутку/масштаб внутри поля, видимые кнопки масштаба и «Вписать». На touch при активной игре не сжимать клетки ниже 32 px: обзор может быть уменьшенным, но открытие в таком обзоре требует увеличения. Ручное перемещение поля не должно открывать клетку в конце жеста.

### Сценарий эффектов

| Событие | Эффект | Ограничение |
| --- | --- | --- |
| Pointer down | Верхняя плоскость уходит вниз, персонаж напрягается | 60–80 мс; pointer cancel снимает состояние |
| Открытие числа | Плитка раскрывается, цифра появляется с коротким scale | 100–150 мс |
| Открытие пустой области | Волна по дистанции BFS от точки клика, короткий бирюзовый след | До 18 мс на шаг, вся волна максимум 400 мс |
| Флаг | Стойка садится, полотно пружинит, несколько искр | 150–220 мс, 6–10 частиц |
| Chord | Открываемые соседи получают согласованный импульс | Одна короткая серия звука на действие |
| Большая безопасная область | Всплывает «+N клеток», прогресс плавно обновляется | Считать только впервые открытые безопасные клетки |
| Мина | Локальная вспышка, ударное кольцо, осколки, небольшое смещение корпуса | Вспышка 80–120 мс, shake до 3 px и до 180 мс |
| После взрыва | Остальные мины проявляются волной, остаются видны ошибки | Основная сцена до 700 мс |
| Победа | Лаймовая волна, персонаж радуется, два коротких выброса конфетти | До 1,5 с; действия доступны сразу |

У взрыва есть понятный центр — выбранная мина. Осколки двигаются радиально, кольцо расширяется и затухает. Красная заливка всего окна и повторяющиеся вспышки не нужны. Эффекты ограничены содержимым игры и не трясут весь рабочий стол.

Для Canvas начать с лимита 160 одновременно живых частиц, DPR ограничить 2. В покое RAF отсутствует. Повторные события не создают бесконечный хвост. При нагрузке снижать количество частиц и сложность свечения. Не создавать сотни React-компонентов частиц.

Звук при включении: сухой click клетки, короткий pop флага, подъём тона при волне, короткий приглушённый удар при мине, аркадный аккорд победы. Каскад из 100 клеток не играет 100 отдельных звуков. Haptics можно добавить как необязательное улучшение с проверкой поддержки и отдельной настройкой.

### Правила и управление

Сохранить существующие режимы: «Спринт» 8×8/8, «Новичок» 9×9/10, «Любитель» 16×16/40, «Эксперт» 16×30/99. Спринт остаётся компактным полем, без скрытого лимита времени. Новую аркадную систему очков и комбинаций в этот выпуск не вводить.

Мины размещаются после первого успешного открытия вне клетки и её соседей. Первая открытая клетка поэтому имеет ноль соседних мин. Это гарантия безопасного начала; полная решаемость без угадывания не обещается. RNG принимать параметром, чтобы тесты могли воспроизводить поле.

ЛКМ открывает, ПКМ ставит/убирает флаг. По умолчанию цикл «закрыта → флаг → закрыта». Существующее состояние «?» можно включить настройкой: тогда цикл «закрыта → флаг → ? → закрыта». Счётчик равен количеству мин минус число флагов; это оценка игрока, а не число подтверждённых мин, и отрицательное значение допустимо.

Добавить chord: нажатие на открытое число при равенстве числа соседних флагов этому числу раскрывает остальных закрытых соседей. Если флаги стоят неправильно и среди них есть неотмеченная мина, это поражение. При несовпадении числа флагов — кратко подсветить соседей, состояние не менять. В режиме установки флагов tap по открытому числу ничего не открывает.

На touch видимый переключатель «Открывать / Флаг» обязателен. Длинное удержание около 350 мс — дополнительный путь к флагу; движение более 8 px отменяет удержание, последующий click после long press подавляется. Настройки порогов проверить на устройстве.

Клавиатура: один Tab-вход на grid, стрелки перемещают активную клетку, Enter/Space открывают или выполняют chord, F ставит флаг, Home/End переходят по строке. Для скринридера скрытая клетка не раскрывает данные о мине; открытая сообщает координаты и число. Победа — все безопасные клетки открыты, независимо от флагов. После победы/поражения обычные ходы заблокированы.

Экран результата оставляет видимой основную часть поля: статус, фактическое время, сложность, локальный рекорд при его наличии, «Ещё раз» и «Посмотреть поле». Рекорды хранить отдельно по сложностям. Автозаполненных демонстрационных рекордов не создавать.

## 6. Состояние, события, анимация и сохранение

Разделить четыре слоя: чистое игровое состояние; команды/история/таймер сессии; визуальные компоненты; краткоживущие эффекты.

Движок получает команду и возвращает новое состояние вместе с результатом: применена ли команда, какие объекты изменились и какие визуальные события произошли. Некорректные координаты и запрещённые ходы возвращают безопасный отказ без изменения состояния. UI не изменяет карту или клетку напрямую.

Солитер: события раздачи, добора, переноса, переворота, возврата, победы. Сапёр: открытие клеток с дистанциями BFS, изменение флага, взрыв с координатой центра, победа. Полное логическое состояние применяется сразу; анимация проигрывает его представление. Повторный click во время волны не обрабатывает уже открытую клетку второй раз.

Эффекту назначить идентификатор сессии и порядковый id команды. Звук и частицы воспроизводятся один раз, включая React Strict Mode. Side effects не запускать внутри reducer или updater-функции `setState`. При restart, Undo, закрытии или размонтировании отменять старые animation handles/таймеры; асинхронный callback сверяет id сессии.

В dnd-kit внешний слой управляет координатами drag. Вложенный слой Motion отвечает за подъём/наклон/переворот. После drop геометрия перехода имеет одного владельца; исключить одновременную запись CSS transition, Motion layout и drag в один transform. Не предполагать, что общий `layoutId` сам решит перенос между разными родителями и overlay: сначала проверить на рабочем вертикальном срезе.

Состояние сессии хранить в provider/store выше размонтируемого содержимого окна; React Context с reducer или внешний store на `useSyncExternalStore` достаточен. Изолировать подписки двух игр. Сохранение состояния в localStorage — дополнительная устойчивость при обновлении страницы. Каждая принятая команда сохраняет новый снимок; время сохранять с ограниченной частотой и при паузе. Ошибка storage не ломает игру и не показывает ложное «Сохранено».

Ключи: `amazi.games.solitaire.v1`, `amazi.games.minesweeper.v1`, `amazi.games.preferences.v1`. Снимок включает schemaVersion, game/rules version, id сессии, состояние, время и настройки режима. Для солитера сохранить Undo-историю. При превышении quota оставить игру и историю в памяти, сообщить кратко о невозможности сохранения. При восстановлении проверить схему и игровые инварианты до показа. Повреждённый снимок даёт новую партию с понятным сообщением.

Таймер измеряет активное игровое время через монотонный источник в текущей сессии; обновляет видимый счётчик примерно раз в секунду. Первый принятый игровой ход запускает его. Сворачивание, закрытие, скрытая вкладка и явная пауза останавливают накопление; потеря фокуса в пользу другого окна также ставит игру на паузу. Возврат показывает «Продолжить», чтобы отсчёт не запускался неожиданно. При паузе поле закрыто нейтральной подложкой. Новая игра и смена сложности при незавершённой партии показывают компактное подтверждение сброса.

## 7. Загрузка, адаптивность и доступность

Обе игры загружаются через `next/dynamic` из клиентского router только при открытии нужного окна. Библиотеки эффектов также загружать по необходимости. Не обращаться к `window`, AudioContext и localStorage при импорте модуля. Для случайной раздачи либо создавать состояние после клиентского mount, либо отключить SSR конкретного игрового компонента из клиентской границы; не допускать разных случайных раскладов при гидратации.

Для поля использовать container queries/ResizeObserver по размеру содержимого окна. Breakpoints только по viewport недостаточны: пользователь может сделать окно маленьким на широком экране. Геометрию пересчитывать после resize, изменения масштаба и прокрутки; во время drag учитывать актуальные координаты. Overlay не должен перекрывать чужие окна поверх их z-index.

Выполнить обычный, развёрнутый и мобильный режимы. Горизонтальная прокрутка допускается внутри сложного поля, но не растягивает страницу портфолио. Панели доступны при 200% масштабировании. Для desktop-поля допустим компактный размер, а основные кнопки на touch имеют достаточную площадь нажатия около 44×44 px.

Ввести пользовательскую настройку эффектов «Полные / Спокойные». Системный `prefers-reduced-motion` задаёт верхнюю границу: отключает shake, 3D-перевороты, пролёты и частицы, сохраняя мгновенные изменения и короткое затухание. Применить и к Motion, и к custom canvas, и к confetti. Возможности Motion для этого описаны в [документации по доступности](https://motion.dev/docs/react-accessibility).

Фокус всегда заметен. Названия карт, счётчики и статусы имеют доступные подписи. Для сапёра использовать roving tabindex, чтобы Tab не проходил 480 клеток. Скринридер не получает по отдельному сообщению на каждую клетку большого каскада; объявлять итог одного действия. Правила и настройки доступны во время партии, диалоги управляют фокусом и возвращают его к инициатору.

### Этап 6. Проверить, отполировать, передать

Запустить проверки из раздела 10. Исправить найденные дефекты. Записать короткие демонстрации реального взаимодействия: перенос и Undo в солитере; раскрытие, flag/chord и взрыв в сапёре. Снять финальные скриншоты. Сравнить начальную загрузку портфолио до/после. Передать результат с фактическими данными, не заменяя их словами «всё работает».

Первый выпуск включает оба законченных визуальных направления и обязательные сценарии документа. Добор по три карты, дополнительные колоды, no-guess solver, ежедневные задания, аккаунты и сетевые рейтинги — отдельное развитие после этого выпуска.

## 10. Проверки и критерии приёмки

### Корректность движков

Солитер: после любой последовательности команд ровно 52 уникальные карты; правила мастей/рангов/переноса последовательности соблюдены; закрытую или внутреннюю карту основания перенести нельзя; некорректный ход и пустой добор не меняют состояние. Undo восстанавливает перенос вместе с автоматическим переворотом, проход запаса и автозавершение. Подсказка указывает конкретную карту. Победа распознаётся только после заполнения четырёх оснований. Сохранение/загрузка сохраняют порядок и историю.

Сапёр: на всех уровнях точное число мин; первый ход и соседи безопасны; соседние числа правильны на краях/углах; flood fill открывает только допустимые клетки. Проверить оба цикла флага, отрицательный счётчик, корректный chord, chord с неверными флагами, отсутствие открытия при несовпадении счётчика. Победа требует всех безопасных клеток; обычные команды после окончания ничего не меняют. Флаг до первого открытия не генерирует поле и не запускает таймер.

Общее: malformed сохранение, отказ localStorage, reload, сворачивание/разворачивание, переключение окна и скрытая вкладка не ломают сессию. Победа, звук и эффекты не дублируются в Strict Mode. После restart старые callbacks не меняют новую партию.

### Браузерные сценарии

1. Солитер: перенести последовательность drag, сделать недопустимый drop, повторить ход через выбор источника/цели и клавиатуру, отменить; свернуть и восстановить.
2. Солитер: добрать весь запас, выполнить повторный проход, Undo; восстановить страницу; завершить тестовый близкий к победе расклад легальными командами.
3. Сапёр: первое открытие у края, большой каскад, флаг правой кнопкой, long press и touch-переключатель, chord, поражение, restart в процессе эффекта.
4. Сапёр: закончить тестовую почти выигранную партию, проверить рекорд только её сложности; открыть expert и прокрутить поле без случайных кликов.
5. Открыть обе игры; проверить переключение фокуса, горячие клавиши, паузу, mute и reduced motion.

Для близких к победе сценариев использовать внутренние тестовые fixtures через тестовый контур. Не оставлять пользователю кнопку фальшивой победы и не включать тестовые результаты в статистику.

### Визуальная приёмка

Проверить viewport 1440×900, 1280×800, 768×1024 и 390×844, отдельно узкое окно на широком экране, 200% browser zoom и системный reduced motion. Использовать production build для итогового ощущения скорости, Chromium и минимум один из WebKit/Firefox; touch проверить эмуляцией и на реальном устройстве, если оно доступно. Если реального устройства нет, явно указать ограничение.

Обязательные кадры солитера: общий расклад, крупные A/7/Q/K и рубашка, перенос последовательности, галерея, узкий экран, победа. Обязательные кадры сапёра: готовое поле, открытая область с числами/флагами, поражение с ошибочным флагом, победа, expert с навигацией, touch-панель.

Критерии визуального качества: все угловые индексы видны; графика фигур отличается и составляет серию; стол имеет глубину; золото поддерживает рисунок; панели не конкурируют с картами. У сапёра ясно различимы нажатая/закрытая/открытая клетки, числа читаются без остановки анимации, взрыв имеет центр и короткое завершение. Нет обрезанных кнопок, слоёв поверх чужих окон, системных emoji вместо авторских игровых иллюстраций.

### Производительность и команды

Ориентир — устойчивые 60 fps на обычном desktop в production при переносе карт и раскрытии поля. Это проверить записью Performance, указав среду. Обработчики не должны ждать завершения декоративной анимации; целевой отклик на ввод — до 100 мс в проверяемой среде. В покое отсутствуют RAF-циклы частиц, таймер обновляет только нужные части UI, закрытые игры не проигрывают звук и эффекты.

Добавить npm scripts `test:games` для `vitest run tests/games` и `test:e2e:games` для `playwright test e2e/games`, согласовав конфигурацию с проектом. Итоговые команды:

```powershell
npm run lint
npm exec tsc -- --noEmit
npm run test:games
npm run build
npm run test:e2e:games
```

Playwright настроить на доступный проверочный сервер; браузеры установить при подготовке окружения. Фиксировать существующие несвязанные ошибки отдельно от новых. В отчёте перечислить действительно выполненные команды и результаты. Если проверка не выполнена, указать причину.
