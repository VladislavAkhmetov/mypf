# Antigravity: исправления основы и готовая системная графика

Работай в текущем проекте, сохрани незакоммиченные изменения. Лид сейчас делает лендинг. Не меняй `src/components/portfolio/` и композицию лендинга. В `portfolio-browser-window.tsx` исправляй только состояние/навигацию, сохраняя подключение PortfolioLanding и его контракт. Перед правкой перечитывай файл.

## 1. Закрой три воспроизведённых дефекта

Проверено лидом в Chromium на production-сборке:

1. Открыть `?view=portfolio&focus=engineering`, затем в этой же вкладке перейти на `?view=portfolio`: остаются 3 проекта вместо 12. Явный URL должен иметь приоритет над sessionStorage, включая отсутствие focus и неизвестный focus.
2. Открыть общий каталог, нажать Kora, нажать Back настоящего браузера: URL уже `?view=portfolio`, но h1 всё ещё Kora. Локальное состояние и props расходятся. Сделай один источник состояния навигации, а не очередную условную синхронизацию одинаковых initial props. Проверь также Forward, закрытие/открытие, unknown project после сохранённого кейса и возвращение к подборке.
3. Открыть `?project=kora`, прокрутить содержимое до scrollTop=250, свернуть и восстановить: scrollTop становится 0. Храни прокрутку каталога и каждого кейса раздельно; сворачивание кейса не должно затирать позицию каталога. При открытии нового кейса начинай сверху.

Исправь связанные проверки: сейчас сценарий 5 не проверяет scrollTop, сценарий 6 проверяет только toBeVisible (не попадание кнопок в viewport), сценарий 7 содержит условный if, который позволяет пропустить клавиатурную проверку. Обязательные assertions должны выполняться всегда. Добавь регрессионные сценарии выше. Селекторы не привязывай к старому заголовку «Портфолио проектов»: композиция меняется, действия и URL остаются.

После внедрения лендинга все восемь существующих сценариев вывели `ok`, но процесс Playwright завис при teardown webServer и был остановлен лидом. Проверь корректное завершение своего тестового Next.js-процесса на Windows; не завершай чужие dev-серверы. Успешные assertions при зависшем runner не означают чистое завершение команды.

## 2. Готовые иконки и курсоры

Не рисуй новый набор SVG вручную. Найди один качественный согласованный готовый набор в эстетике Windows XP / ранних Windows: объёмные цветные системные иконки, папки, документы, приложения. Нужны варианты для 16–24 px панелей и 48–64 px рабочего стола. Исключи emoji, случайную смесь наборов и современные одноцветные outline-иконки. Проверь фактические условия использования/атрибуцию у источника; не приписывай лицензии. Если набор требует покупки/учётной записи, не покупай: зафиксируй ограничение, продолжай независимые исправления.

Сам выбери лучший готовый набор по этим критериям и подключи через существующий общий интерфейс иконок. Не запрашивай выбор между вариантами. Сохрани реальные источники и требуемую атрибуцию. В сдаче приложи один контактный лист установленного набора: папка, файл, Word, PDF, браузер, компьютер, корзина на тёмном и светлом фоне в двух размерах. Если какого-то приложения нет, используй соответствующую общую иконку документа/приложения из того же набора; не дорисовывай её в другом стиле. Не извлекай системные ресурсы из неизвестных исполняемых файлов.

Курсоры: убери самодельные SVG/data URI и используй стандартные CSS default, pointer, text, move/grab/grabbing, resize и wait по назначению. Сохрани совместимый экспорт xpCursors, проверь дополнительные inline/CSS-переопределения. Не делай cursor:none и слежение декоративного указателя за мышью.

## 3. Файлы и папки

Замени файловые/папочные emoji и разрозненные inline SVG выбранным набором через общий интерфейс. Это относится и к содержимому папок, и к меню, и к заголовкам окон. Не меняй игровую графику, знаки в содержимом документов и авторскую графику лендинга. Композицию файлового интерфейса пока сохрани: её размер, плотность, состояния и превью определит лид.

## Сдача

Сам исправь свои ошибки, запусти lint, typecheck, build и целевые Playwright-тесты. Добавь проверки console/pageerror и численные проверки scrollTop/геометрии; итог PASS должен означать выполненные assertions. Изменения общего менеджера окон проверь игровым smoke-набором. Обнови прежний отчёт фактическими результатами, не повторяй весь старый аудит. Ответ до 12 строк: результаты трёх регрессий, команды PASS/FAIL, контактный лист и источники, ограничения. Не называй полный редизайн завершённым.
